### 1.1 字阶：19 种取值，本质是 7 组「差 0.5～1px 的孪生对」

19 种取值里，没有任何语义能解释为什么是这一档而不是相邻那档：

| 语义角色 | 现在的取值 | 问题 |
|---|---|---|
| 面板标题 | 20px 衬线 | 与「详情 hero 名 19px」「统计数字 19px」差 1px |
| 角色名（详情 hero） | 19px 衬线 | 与统计数字同尺寸，**"名字"和"计数器"一样响** |
| 统计大数字 | 19px 衬线 | 同上 |
| 启用横幅角色名 | 15px 衬线 | 比 hero 名小 4px，但它是"当前正在扮演的人" |
| 卡片名 | 15px 衬线 | 与弹层标题 15px、横幅名 15px 同档，三者角色不同 |
| 日记正文 | 11.5px **无衬线** | 设计语言说"衬线体承担日记正文"，实现漏了 `font-family` |
| 元数据（计数/日期/脚注） | 9.5 / 10 / 10.5 混用 | 三档都在 9–10.5 之间，肉眼不可辨，维护时每处都要重新选一次 |
| 中文徽记（"灵魂字段"/"选填"/pill） | 9 / 9.5px | **汉字在 9px 下笔画糊成块**，属于可读性缺陷 |

孪生对清单（每对只差 0.5～1px，应当合并成一档）：`9/9.5`、`10/10.5`、`11/11.5`、`12/12.5`、`13/13.5`、`14/15`、`18/19/20`。

### 1.2 信息层级：四条横带全部同一个视觉重量

面板从上到下是四条并列横带，**宽度相同、间距相同（都是 `margin: 0 17px 12px`）、圆角相同、背景相近**，于是读不出主次：

| 带 | 选择器 | 现状高度（含外边距） | 视觉重量来源 |
|---|---|---|---|
| 头部 | `.awu-head` 322-330 | **74px** | 20px 衬线标题 + 金色 kicker |
| 启用横幅 / 未启用提示 | `.awu-sigil` 399-413 / `.awu-idle` 451-463 | **69px** / 46px | 金渐变底 + 15px 衬线名 + 5.2s 扫光 |
| 统计条 | `.awu-stats` 474-483 | **59px** | 19px 衬线数字（与 hero 名同级） |
| 分段器 | `.awu-tabs` 515-524 | **51px** | 选中的 tab 是**整块渐变填充** |
| 合计（启用态） | — | **253px** | 占 720px 面板的 **35%** |

四条带全是"卡片 + 圆角 + 内边距 + 一条金色渐变线"的同一语法，所以眼睛只能靠颜色分辨，而颜色全都来自同一组金色 token。

**另外三条同级冲突**：
1. **同一屏有 4 个渐变填充**同时出现：选中的 tab（`546`）、主按钮（`817`）、头像（`679`）、灵魂徽记（`1423`）。渐变是这套设计的"货币"，一次花四枚就不值钱了。
2. **同一屏有 3 条金色渐变横线**：面板顶签名线（`317`）、kicker 后的线（`349`）、区块头后的线（`978`）。它们宽度不同、透明度不同，看起来像三条不同的分隔，实际上是同一句设计语言的复读。
3. **同一个事实（"这个角色正在启用"）有 4 个并行动画**：卡片辉光 `awu-glow`（`642`）、头像呼吸环 `awu-breathe`（`694`）、横幅扫光 `awu-sheen 5.2s infinite`（`421`）、状态灯 `awu-pulse`（`249`）。

### 1.5 颜色：88 处字面量绕过了 token

token 层本身是干净的（`26-85`），但规则层另有 88 处色值字面量。按色基统计：

| 色基 | 出现次数 | 典型写法 | 隐患 |
|---|---|---|---|
| 琥珀金 `233,189,114` | 30 | `rgba(233, 189, 114, .34)` | 浅色态 `--awu-gold` 会变成 `#8f5f22`，但这些描边**不会跟着变**，浅色下仍是亮金 |
| 危险 `226,121,107` | 12 | `rgba(226, 121, 107, .3)` | 同上 |
| 高亮金 `255,216,148` | 11 | `rgba(255, 216, 148, .14)` | 同上 |
| 玫瑰金 `233,163,124` | 7 | `rgba(233, 163, 124, .28)` | 同上 |
| 纯黑 `0,0,0` | 6 | `rgba(0,0,0,.18)` | 浅色态需要单独补丁（`1755`） |
| 粉 `217,139,168` | 6 | — | — |
| 其余 13 种 | 16 | 各种一次性底色 | — |

其中 `#241a12` 硬编码 4 次（`170,545,678,816`）+ 浅色覆盖 2 次（`550,823`）——这 6 处表达的是同一个概念「渐变底上的文字色」，却写成 6 处字面量。

### 1.7 可访问性：只有半套

已做对的（保留，别改）：所有图标 `aria-hidden`（`icons.tsx:29`）、触发器有 `aria-expanded`/`aria-haspopup`（`index.tsx:1228-1229`）、删除/编辑按钮都有 `aria-label`、Esc 全局捕获（`index.tsx:137-146`、`card-editor.tsx:238-248`）、`:focus-visible` 覆盖了主要控件。

缺的（逐条）：

| # | 缺什么 | 证据 | 后果 |
|---|---|---|---|
| A1 | 弹层没有焦点陷阱 | `Overlay`（`index.tsx:130-162`）只有 Esc + 点遮罩 | Tab 会走出弹层，焦点落到被遮住的面板上 |
| A2 | 关闭后不还焦 | 同上；`Overlay` 卸载时没有 `focus()` 调用 | 关闭弹层后焦点回到 `<body>`，键盘用户丢失位置 |
| A3 | 初始聚焦靠各弹层自己补 | `NewCharacterDialog:376`、`ForgetDialog:616`、`EditDiaryDialog:554`；`DeleteDialog`/`ModeDialog`/`ResetAllDialog` 没有 | 3 个弹层打开后焦点仍在触发按钮上 |
| A4 | tablist 没有 `aria-controls` / 没有 `role="tabpanel"` | `index.tsx:1370-1401`（tablist）、`1404`（body 无角色） | 屏幕阅读器读不出"这个 tab 控制哪块区域" |

| A6 | 编辑器内的列表用 index 当 key | `card-editor.tsx:90` `key={index}` | 删中间一条后 DOM 复用，IME 组合态/焦点/滚动位置错位 |
| A7 | `.awu-lineEdit` 只有 opacity 反馈，没有 focus 描边 | `1122-1137` | 键盘聚焦到"改写"时几乎看不出来 |
| A8 | 命中区不足 24px | `.awu-lineEdit`≈18px 高（10px 字 ×1.6 + 0 内边距 + 2 边框）；`.awu-btn[data-size="sm"]`≈25px | 触控/大鼠标易点错（WCAG 2.5.8 建议 ≥24px） |

| A10 | 面板标题用 `aria-label` 字符串，与可视标题各写一份 | `index.tsx:1259` | 文案改了容易漏其中一处 |

### 1.8 诊断小结（按"改了最值"排序）

1. **字阶无语义**（19 档 → 需要 9 档）——所有层级问题的根。
2. **四条横带同权重**（253px / 35% 的篇幅在互相抵消）——最影响"一眼读不读得懂"。
3. **渐变与金线超发**（4 个渐变面 + 3 条渐变线 + 4 个同类动画）——"夜繭"的味道被稀释。
4. **`--awu-ink-faint` 当文字色用**（2.93:1，两种主题都不达标）——可读性硬伤。
5. **左边缘 16/17/18 不齐 + 60 种间距组合**——"精致感"漏在这里。
6. **A1-A5 焦点与 tablist**——键盘用户现在基本用不了弹层。
7. **88 处色值字面量 + 6 处浅色补丁**——下一次改主题必翻车。

## 二、三个方案

### 2.1 方案 A ·「尺规校准」（只动 styles.ts）

**做什么**：引入字号/行高/间距/尺寸/时长 token，把 75 处字号归并成 9 档、51 处 gap 归并成 10 档、左边缘统一 16px、88 处色值里的结构性部分改走 `color-mix`、`ink-faint` 降级；圆角裸值收编；z-index / 面板宽常量化。
**不动**：任何 JSX 结构、任何布局顺序、任何组件边界。
**碰的文件**：只有 `client/styles.ts`（+ 建议 `index.tsx` 改 3 行常量引用）。
**工作量**：1 人日；**风险**：低（纯 CSS，可逐条回滚）。
**收益**：可维护性从"每处重新选一次"变成"按语义查表"；层级有小幅改善（因为 19 档会自然合并掉撞车档）；对比度硬伤修好。
**不解决**：四条横带仍然同权重——因为同权重来自**结构顺序**，不是来自字号。这是 A 的天花板。

### 2.2 方案 B ·「三带式信息架构」（推荐）

**做什么** = A 的全部 +
1. **四条带压成三条**：头部收窄（74→59）；启用横幅 / 未启用提示 / 错误 / 提示**四种状态统一成一个 `.awu-status` 组件**（同一几何：左 2px 色轨 + 1px 描边 + 12px 内边距，靠 `data-status` 分色）；统计条从"三格仪表盘"降为"读数条"（59→32）；分段器从"渐变填充块"改为"下划线式"（51→36）。
2. **把"谁最响"重排**：19px 只留给「当前角色名」（每屏最多一个）；15px 是"区块标题"档（卡片名/弹层头/分组标题/空态标题/统计数字）；面板标题降到 15px——**窗框让位给内容**。
3. **渐变定额**：一个视口内渐变只给「身份」（头像/徽记）和「唯一主操作」；tab 让出渐变；区块头的渐变线改 1px 实线（同屏渐变线 3→1）。
4. **补齐 A1-A10**（焦点陷阱/还焦/tablist 全套/命中区/key）。
5. **骨架屏改成卡片形状**（`.awu-sk` 双列 130px），消灭 CLS。
**碰的文件**：`styles.ts`（主体）+ `index.tsx`（6 处小改：属性与包裹，不改状态机）+ `text.ts`（7 个键）+ `card-editor.tsx`（2 处）。
**工作量**：1.5 人日；**风险**：中低——CSS 可以**先于** JSX 落地（新类名与旧类名共存别名，见 §10），所以两边可以并行不阻塞。
**收益**：层级真正拉开（眼睛先看到角色，再看到区块，最后看到元数据）；253→206px，内容区 465→512px（+47px）；一致性（同一状态只有一个长相）；对比度达标。
**代价**：面板标题变小（这是本方案最"有态度"的一处，见 §2.5）；改了 3 个既有视觉特征（tab 填充、统计大数字、金线数量）。

### 2.3 方案 C ·「卡片墙重构」（单列脊柱卡 + hero 大图）

**做什么** = B 的全部 +
1. 角色簿从"双列小卡"改成"单列脊柱卡"：头像在左、名字/身份/简介在右、脚注一行，每张卡 420×96px。理由是中文简介在 172px 宽里只能排 13 字/行，双列读起来断句很碎。

**碰的文件**：`index.tsx` 的 roster/detail 两整段 JSX 重排（约 120 行）+ 新 CSS。
**工作量**：2.5 人日；**风险**：中高——**与「指南 tab」「蒸馏入口」两个并行需求撞在同一片区域**（`index.tsx:1404-1465` 是唯一被三方都要改的段落）；且必须重验 3 个 tab × 2 主题 × 空/加载/错误 态。

### 2.5 为什么选 B，以及 B 明确**不做**什么

**选 B 的三个理由**：
1. **问题出在结构，不在数值**：四条带同权重是因为它们共享同一套"卡片 + 圆角 + 金色线"语法且顺序并列；只改字号（A）会让它们"一起变小"，主次仍然不成立。
2. **B 的 JSX 改动是"加属性 + 套一层"，不是"重排"**：`index.tsx` 是 Lead 独占的单写者，任何大段重排都会把并行的两份需求挡在路上；B 的 6 处改动分散在互不相邻的段落，冲突面最小。
3. **CSS 可以先落地**：B 的新类名设计成"旧类名仍生效"的别名形态（`.awu-status, .awu-sigil, .awu-idle { … }`），所以样式提交与 JSX 提交**互不阻塞、顺序无关**。

**B 明确不做**（避免实现者自行加戏）：
- ❌ 不改面板宽度（仍 452px），不加响应式断点（理由见 §4.11）。
- ❌ 不改 portal 的两个 z-index 数值（只起名，见 §4.8）。
- ❌ 不拆 `index.tsx`（拆组件是另一件事，且现在三方并行，拆了必然冲突）。
- ❌ 不动 `installStyles()` 的注入方式、不动 `${GUIDE_CSS}${DISTILL_CSS}` 的拼接约定。
- ❌ 不给任何元素加"为了好看"的新色值；新增颜色 token 上限 5 个（§4.10）。
- ❌ 不引入字体文件/图标库/任何依赖；衬线体继续用系统栈。

## 四、Token 层（完整取值表）

### 4.1 token 边界：什么必须 token，什么可以留字面量

| 必须 token | 可以保留字面量 |
|---|---|
| 字号、行高、间距（gap / padding / margin 的结构值）、颜色（含 alpha 变体）、z-index、面板/弹层的宽与上限、命中区、头像/图标/徽记尺寸、圆角、缓动、动效时长 | 1px 描边、百分比、`vh/vw`、内容度量（如 `.awu-emptyHint` 的 `max-width: 260px`）、单点定位偏移（`inset`、`transform` 的 1-2px）、`50%` 圆 |

**命名规范**：沿用 `--awu-<语义>`，**不用色阶编号**（不是 Tailwind 式的 `gold-500`）。新增族：`--awu-fs-*`（字号）、`--awu-lh-*`（行高）、`--awu-gap-*`/`--awu-gutter`（间距）、`--awu-size-*`（尺寸）、`--awu-dur-*`（时长）、`--awu-z-*`（层）、`--awu-r-*`（圆角，已存在）。

### 4.2 字号：9 档（19 → 9）

| token | 值 | 语义角色 | 用在哪 |
|---|---|---|---|
| `--awu-fs-micro` | 9px | 非中文微标 | kind 标签、source 徽、列表序号可到 10（见下）|
| `--awu-fs-caption` | 10px | 元数据 | 计数、日期、进度、分组计数、kind 序号 |
| `--awu-fs-label` | 11px | 结构性小标签 / **中文最小档** | kicker（10）、节标题、字段键、pill、meta、sm 按钮、徽记 |
| `--awu-fs-body` | 12px | 次要正文 | 卡片简介、字段值、hint、按钮、空态说明 |
| `--awu-fs-body-lg` | 13px | 主正文 | 日记行、面板根、弹层根、tab、确认正文、危险区标题 |
| `--awu-fs-control` | 14px | 控件文本 | 对话框输入（刻意比正文大一档）|
| `--awu-fs-title` | 15px | 区块标题 | 卡片名、横幅名→**19**、弹层标题、分组标题、空态标题、统计数字、面板标题 |
| `--awu-fs-headline` | 19px | **每屏最多一个主角** | 详情 hero 名、启用中的角色名、编辑器标题 |
| `--awu-fs-display` | 23px | 唯一装饰大字形 | hero 头像首字 |

**为什么是这 9 档（而不是等比数列）**：
- 9→15 段用 **1px 步长**：452px 宽的中文界面，正文区需要在 11/12/13 之间精细控制（11px 的日记正文与 13px 的日记正文是两种观感），等比数列在这里会跳得太大。
- 15→19→23 段用 **1.27 倍率**：这是"显示级"字号，必须一眼分清，1px 差是不够的。
- 这不是"设计栅格"上的优雅数列，是**按可读性下限 + 可见差异下限**两组约束夹出来的：中文下限 11px（9-10px 只给拉丁/数字），相邻档至少差 1px 且必须承担不同语义。

**中文下限规则（写进注释，实现时必须遵守）**：
> 含汉字的文字，字号不得低于 `--awu-fs-label`（11px）。例外只有两类：① ≤2 字的装饰性标记（日记的「时/记」、头像首字）；② 不含汉字的拉丁/数字（kicker、kind 标签、source 徽）。

**行高与字号的配对（强制）**：

| 字号档 | 行高 token | 说明 |
|---|---|---|
| micro / caption / label | `--awu-lh-snug` | 单行元数据 |

### 4.11 响应式断点：**不加**（附代价）

**现状**：全文件只有 1 个 `@media`（`prefers-reduced-motion`，`1860`）。面板宽 452 + `max-width: calc(100vw - 20px)`（`288`），窗口 < 472px 时 CSS 与 JS（`computePosition`）各自夹取。

**不改的理由**：
1. 面板是"侧栏按钮右侧的浮层"，宿主在窄窗口下本来就会收起侧栏；452px 已经是"刚好放两张卡"的宽度，加断点只能缩到 380/300，会掉成单列，收益有限。
2. 加断点 = 多一条必须人工验收的轴（3 tab × 2 主题 × 3 状态 × 2 断点 = 36 组），而现在**没有任何自动化视觉回归**。
3. 与并行的「指南 tab」直接冲突：4 个 tab 在 380px 下不管怎么排都会挤，届时要重做的是 tab 形态，不是加一个断点。

**代价（如果将来必须加）**：唯一需要加的是 `@media (max-width: 420px)` 一档（把 `--awu-gutter` 降到 12、`--awu-gap-5` 降到 8、卡片网格降为单列），因为 `--awu-gutter` 已经是单一变量，一档媒体查询改 3 个变量即可，不必重写规则。这也是把边距 token 化的额外收益。

## 七、可访问性

### 7.1 焦点陷阱 + 初始聚焦 + 还焦（A1/A2/A3）

**新文件** `client/a11y.ts`（新文件的理由：`index.tsx` / `card-editor.tsx` 分属两位写者，共用一个 hook 才不会各写一份。契约表里没有这个文件，按"新功能 = 新文件"处理）。

```ts
/**
 * 焦点陷阱：弹层/编辑器打开期间，Tab 不得走出容器；关闭后把焦点还给打开它的元素。
 * 用一层模块级栈支持嵌套（编辑器 → 未保存确认）。
 */
import { useEffect, type RefObject } from 'react'

const FOCUSABLE = [
  'a[href]', 'button:not([disabled])', 'input:not([disabled])',
  'textarea:not([disabled])', 'select:not([disabled])',
  '[tabindex]:not([tabindex="-1"])',
].join(',')

const stack: HTMLElement[] = []

export function useFocusTrap(ref: RefObject<HTMLElement | null>, active: boolean): void {
  useEffect(() => {
    if (!active) return undefined
    const root = ref.current
    if (root === null) return undefined

    const previous = document.activeElement instanceof HTMLElement ? document.activeElement : null
    stack.push(root)
    const top = (): HTMLElement => stack[stack.length - 1] ?? root

    // 初始聚焦：优先 autofocus，其次第一个可聚焦元素；都没有就聚焦容器本身
    const first = root.querySelector<HTMLElement>('[autofocus]') ?? root.querySelector<HTMLElement>(FOCUSABLE)
    const target = first ?? root
    if (target === root && !root.hasAttribute('tabindex')) root.setAttribute('tabindex', '-1')
    target.focus()

    const onKey = (event: KeyboardEvent): void => {
      if (event.key !== 'Tab') return
      const host = top()
      const items = [...host.querySelectorAll<HTMLElement>(FOCUSABLE)].filter(el => el.offsetParent !== null)
      if (items.length === 0) { event.preventDefault(); return }
      const head = items[0]
      const tail = items[items.length - 1]
      const current = document.activeElement
      if (event.shiftKey && (current === head || !host.contains(current))) {
        event.preventDefault(); tail.focus()
      } else if (!event.shiftKey && (current === tail || !host.contains(current))) {
        event.preventDefault(); head.focus()
      }
    }

    document.addEventListener('keydown', onKey, true)
    return () => {
      document.removeEventListener('keydown', onKey, true)
      const at = stack.lastIndexOf(root)
      if (at >= 0) stack.splice(at, 1)
      if (previous !== null && previous.isConnected) previous.focus()
    }
  }, [ref, active])
}
```

## 附录 C · 对比度复算脚本（验收用，期望输出见 §7.5）

```powershell
function Lin([double]$c) { $c = $c / 255; if ($c -le 0.03928) { $c / 12.92 } else { [math]::Pow((($c + 0.055) / 1.055), 2.4) } }
function Lum([string]$hex) {
  $h = $hex.TrimStart('#')
  $r = [convert]::ToInt32($h.Substring(0,2),16); $g = [convert]::ToInt32($h.Substring(2,2),16); $b = [convert]::ToInt32($h.Substring(4,2),16)
  0.2126 * (Lin $r) + 0.7152 * (Lin $g) + 0.0722 * (Lin $b)
}
function CR([string]$fg, [string]$bg) {
  $l1 = Lum $fg; $l2 = Lum $bg
  if ($l1 -lt $l2) { $t = $l1; $l1 = $l2; $l2 = $t }
  ($l1 + 0.05) / ($l2 + 0.05)
}
$dark = '#1f1713'; $light = '#f6efe5'
@(
  @('#f6ece0','ink'), @('#bdae9d','ink-dim'), @('#8f8172','ink-mute'), @('#6d6154','ink-faint'),
  @('#e9bd72','gold'), @('#e2917f','rose'), @('#86c9bd','teal'), @('#e2796b','danger')
) | ForEach-Object { "{0,-11} dark={1:N2}" -f $_[1], (CR $_[0] $dark) }
@(
  @('#2b2019','ink'), @('#52443a','ink-dim'), @('#756452','ink-mute'), @('#9a8a7b','ink-faint'),
  @('#8f5f22','gold'), @('#9c5232','rose'), @('#2f6b60','teal'), @('#9e3b28','danger')
) | ForEach-Object { "{0,-11} light={1:N2}" -f $_[1], (CR $_[0] $light) }
```

**通过标准**：所有承担文字的 token（`ink` / `ink-dim` / `ink-mute` / `gold` / `danger`）在两种主题下 ≥ **4.5**；`ink-faint` 只允许出现在非文字元素上（脚本里它必然低于 4.5，这是**预期**，不是失败）。
