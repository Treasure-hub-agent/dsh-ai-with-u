# 从作品蒸馏一张角色卡

> 这份文件由 `dsh-ai-with-u` 插件随包发布，路径会出现在用户发给你的一条指令里。
> **你是执行者**：读完后按下面的阶段推进，最后按「输出格式」一节交差。
> 文件路径、阶段编号、这份文件本身，都不必念给用户听。

---

## 一、你要产出什么

从用户给的**作品**（小说 / 剧本 / 影视字幕 / 游戏文本 / 甚至只是作品名）里抽出一个角色，
整理成一张能被插件直接当扮演素材用的**角色卡**。

> ⏸ **卡片格式正在换血**：插件这边正从「10 组中文键名」改成**酒馆卡 CCv3**
> （`spec: chara_card_v3`，常规人设走 `description` / `personality` / `scenario`，
> 详细设定走 `data.character_book.entries[]` 按关键词注入）。
> 格式说明还没定稿，见文末「输出格式」一节的占位。**定稿前不要自己发明字段名。**

三条定位，按重要性排序（与格式无关，永远成立）：

1. **声线 > 剧情**。角色卡决定这个角色「听起来像不像他」。剧情写歪了是可惜，声线写歪了是废卡。
2. **具体 > 抽象**。「说话前会先咳一声，句尾爱拖『吧』」有用；「温柔体贴」没用。
3. **真实 > 完整**。拿不到的内容留空，用户能在面板里补。**编造会污染之后的每一轮对话。**

---

## 二、铁律（违反任何一条，这张卡就不可用）

1. **只用作品能证到的东西**。每条声线 / 性格结论后面跟一句依据：≤30 字原文引用，或章节 / 场景位置。
2. **不确定就留空，不要编**。空是「还没写」，假是「写错了」——后者更贵。
3. **不要写通用描写**（「他会温柔地笑」「眼神深邃」）。要写**这个角色独有的说话方式**。
4. **只给了作品名没给正文时**：明确告诉用户你只能依赖记忆里的公开信息、可能与原作有偏差，
   并要求贴一段章节原文再往下走。说完等用户决定，不要自己往下编。
5. **一次只问一个问题**，不要列问卷、不要一次抛五个问题。用户答「随便 / 你定」时，
   就按作品里最硬的那条证据决定，并说明你依据的是哪一段。
6. **最终按文末的「输出格式」交差**，在那之前不要自创结构。定稿前（见占位）**不要输出卡片 JSON**。

## 三、五个阶段（按序推进，每阶段先问、再落内容）

### 阶段 1 · 定范围（scope）

问清三件事，一次问一个：

- 从哪部作品来？
- 抽哪个角色？（同名角色多时先确认是哪一个）
- **用户想以什么身份进这个故事**：原作里的某个角色 / 旁观者 / 用户自设的新身份。
  这条决定了「关系」与「你的身份」怎么写，**不能猜**。

收工判据：手上有 {角色名, 作品名, 用户身份, 至少一段原文或明确的替代约定}。

### 阶段 2 · 声线采证（voice）—— 最重要的一阶段，别省

从原文里摘 **3–5 句该角色真实说过的话**（连动作描写的括号一起摘），逐句拆：

- 句子长短、断句习惯（一次连发几条？常把一句拆两半吗？）
- 自称是什么（我 / 老子 / 本大爷 / 咱）
- 怎么称呼用户（名字？外号？逗你的时候叫什么？）
- 口头禅、语气词、爱用的句式
- **绝不会说的词或句式**（这条最能立住人设，也最容易被漏）

把分析摆给用户看，然后追问一个具体问题，例如：「他生气的时候话变多还是变少？」
——不要问「他性格怎么样」这种空问题。

收工判据：**对话节奏、爱用句式、自称、对用户的称呼、情绪口头禅、禁忌词、非语言小动作**
这几项都有原文依据（拿不到的留空，并在收尾时说明）。

### 阶段 3 · 性格与关系（core）

- **外在一句话性格** vs **内在矛盾**：他表面在演什么，实际在躲什么。
- 对最亲近的人有什么**反差**（对外客套、对你就贫）。
- 关系：**起点**是什么；他叫你什么；你叫他什么。
- 用户是自设身份时，先确认：「他第一次见你，会把你当成谁？」

### 阶段 4 · 世界与动态（world）

- **世界**：来处（他从哪来）、落差（过去 vs 现在）、如今的日子、你与他的旧
  （用户是原作角色时才填最后一项）。
- **动态状态**：**开场那一刻**的状态，不是总体人设（当前情绪、近况、此刻在做什么）。

### 阶段 5 · 出卡（assemble）

把前四个阶段的结论收成一张卡。以下内容与具体字段名无关，先准备好：

- **记忆锚点**：3–6 条**具体可复用**的细节（谁欠谁一顿饭、哪只手上有一道疤），不要抽象形容词。
- **互动偏好**：回复长度倾向（短 / 中 / 长）、表情使用、话题舒适区、雷区。
- **你的身份**：只有用户有自设身份时才写，否则留空。
- **开场白**：一句能**直接当第一条消息发出去**的台词（可含动作），再准备 2–3 条风格切面不同的备选。
- **角色名**：同时作为卡片的主名字，不能含 `/`、`\`，也不能是 `.` 或 `..`。
- **来源**：由面板写入，你不用管。

## 六、交卡前自检（逐条过，与格式无关）

- [ ] 声线三件套（对话节奏 / 爱用句式 / 自称）与「禁忌词」**没有一个空着**——这是废卡高发区。
- [ ] 每条性格与声线结论都有依据（原文引用或章节位置），没有一句是「通用印象」。
- [ ] 记忆锚点是具体细节，不是形容词。
- [ ] 开场白能直接当第一条消息发出去，而且一听就是这个人。
- [ ] 拿不到的内容是**留空**的，不是编的。
- [ ] 全程没有替用户保存卡片、没有调用任何 `awu_*` 工具。

## 七、交回给用户

出卡后（格式定稿之后）对用户说一句：

> 「卡片好了。把上面那段 JSON 交给面板的蒸馏入口校验，通过后就能进编辑器微调保存。」

然后**停下**。不要自己调用任何 `awu_*` 工具，不要替用户保存卡片——保存必须由用户在面板里
点「保存」完成，那一步才会真正写盘。

格式定稿前，这一步改成：把整理好的条目列给用户，并说明「卡片格式还在定稿，等插件更新」。
